# TCL 1:1 行为复刻要求与当前状态

2026-10-09，依据用户确认：此前 IMA/Media3 方案出现收益倒扣，现在先建立与 TCL 原厂一致的实现，再观察实际投放结果。收益倒扣原因尚未确定；实现一致也不能单独证明收益结果会一致。

## 当前边界与实现

用户于 2026-10-09 进一步确认：公开 API 可自行设计；从取得 adurl 开始的整条流程必须执行 TCL 原厂逻辑。

当前接入经过列明边界隔离的原厂 base/media/player，生产源码中的自写解析、状态机和 Tracking 已移除。由原厂 Ad/Config.start 创建控制器、地址加载器和计时器；适配层只在取链接的 JSON 返回位置提供宿主已取得的 adurl。后续 VAST 模型、Wrapper、选材、播放控制、回调、错误处理和 XML 跟踪由原厂执行。XML 类型许可和与在线广告无关的数据库/业务网络边界按隔离清单修改；这不等于全部原件未修改。

- 固定基准：TCL 2.8.02 WATERFALL / lazyLoad / playerType=0，以及 2026-10-08 实测配置。
- 原厂会追加 requestId，Google 链接同样保留此步骤。
- 回调的重复、未发送的事件及原厂异常处理均按原厂执行，不自行去重、补报或替换。
- Google 库存、设备、授权等真实输入在进入处理链之前提供；配置和响应元数据也是输入，不能以省略字段后的另一种行为宣称输入相同。
- 原厂二进制复用和行为对照的验收结果分别记录。当前迁移核验见下方报告。

## 验收证据

1. 原厂二进制版本和来源固定，逐类区分未修改复用、明确适配、独立移植和未覆盖项。
2. 同一输入上下文、配置、VAST XML、播放操作和网络结果下，对照原厂与候选实现的事件/HTTP 序列；核对地址、参数、次数、触发条件和顺序。
3. 除成功样本，还要覆盖空广告、Wrapper 分支、不同素材、不可见/暂停/切换、加载/播放错误、超时、保底、重复调用和释放后的迟到回调；原厂不支持的能力也应如实记录，不能擅自补功能后称为相同。
4. 原厂对照尚未覆盖的项保持“未核验”；不会把一次真实投放成功等同于全部分支相同。

## 执行范围补充

用户进一步确认：保留最小侵入的原厂广告执行方案，但必须禁止所需广告链路之外的执行。当前按 ISOLATION.md 删除/封禁 TCL BI、业务数据库、配置/取链接网络、持久标识及计数；XML 仅允许原厂广告模型。副作用隔离与广告行为对照是两项独立验收，不再以整包字节一致推导隔离成立。

2026-10-10：隔离版验收和真实链接证据见 [隔离报告](../artifacts/tcl-isolation-20261009/report.md)。同进程新链接交接已实测；未 release 直接复用的间歇停播仍是记录中的限制，独立广告机会采用宿主显式调用原厂 release 的生命周期，不在 SDK 内重写播放或回报。
