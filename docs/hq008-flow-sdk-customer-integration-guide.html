ANDROID · PURE JAVA · TCL VIDEO AD SDK 2.8.02

HQ008 流程控制 SDK
客户接入说明

用于接入定时调度、flow-control、authorize 与广告事件上报。客户继续使用自己现有的 TCL 广告播放及 UI 代码。
文档版本：1.0
SDK：hq008-flow-sdk
更新日期：2026-07-16

1. 接入范围

流程控制 SDK 负责：

  • 进程内定时调度；
  • 调用 sdk/flow-control；
  • 调用 sdk/authorize；
  • 授权通过后通知当前广告 UI；
  • 接收广告加载、开始、完成、失败事件并自动上报；
  • 根据服务端 next_request_seconds 安排下一轮。

客户继续负责：

  • TCL 视频广告 SDK 的依赖和初始化；
  • 广告窗口、容器、尺寸、位置和页面生命周期；
  • 声音、展示方式以及其他播放策略；
  • 应用本身的进程存活。
流程 SDK 不包含 CMP，不处理窗口、尺寸、声音或有感/无感播放配置。

2. 引入 AAR

将 hq008-flow-sdk-release.aar 放入客户项目的 app/libs，并在应用模块添加：

dependencies {
    implementation files('libs/hq008-flow-sdk-release.aar')
    implementation 'com.squareup.okhttp3:okhttp:4.9.3'
    implementation 'com.google.code.gson:gson:2.8.9'
}

流程 SDK 源码及公开 API 均为 Java，并与客户项目现有的 OkHttp 4.9.3、Gson 2.8.9 保持一致，避免重复版本和依赖冲突。客户现有的 TCL 视频广告 SDK 依赖保持不变。

3. Application 初始化

在客户 Application.onCreate() 中初始化流程 SDK。init() 会自动启动全局定时流程：

public final class CustomerApplication extends Application {

    @Override
    public void onCreate() {
        super.onCreate();

        Hq008FlowSdk.init(
                this,
                "TCL_FFA"
        );

        // 客户原有的 TCL 视频广告 SDK 初始化逻辑继续保留
    }
}
channelId 必须使用双方约定的正式渠道值，示例中的 TCL_FFA 需要按实际渠道替换。

4. 注册广告授权回调

下面代码放在真正能够展示广告的 Activity、Service、Fragment 或业务控制器中，不要求写在 Application。

private Hq008AdSession currentAdSession;

private final Hq008AdCallback hq008AdCallback = new Hq008AdCallback() {
    @Override
    public void onAdAuthorized(Hq008AdSession session) {
        currentAdSession = session;

        // 调用客户当前已有的广告请求方法
        requestAd();
    }
};

@Override
protected void onStart() {
    super.onStart();
    Hq008FlowSdk.setAdCallback(hq008AdCallback);
}

@Override
protected void onStop() {
    Hq008FlowSdk.clearAdCallback();
    super.onStop();
}
Hq008AdCallback 只有一个方法：当 flow-control 与 authorize 都通过后，SDK 回调 onAdAuthorized(session)，客户开始播放广告。

SDK 定时触发会独立请求后台；没有广告回调时不会阻塞后台请求，只是不派发展示。

5. 在现有广告回调中加入会话通知

客户不需要修改广告请求方式，只需在对应回调位置加入以下调用。

广告事件位置 加入的流程 SDK 调用
onAdLoaded(controller) currentAdSession.loaded();
onAdStartPlay() currentAdSession.started();
onAdStartPlay(progress) currentAdSession.started(progress);
onAdFinished() currentAdSession.completed();
onAdError(errorCode) currentAdSession.failed(errorCode, "TCL_AD_ERROR_" + errorCode);
onContainerSizeError() currentAdSession.failed("TCL_CONTAINER_SIZE_ERROR");

播放完成

@Override
public void onAdFinished() {
    if (currentAdSession != null) {
        currentAdSession.completed();
        currentAdSession = null;
    }

    // 客户原有的广告完成处理继续执行
}

播放失败

@Override
public void onAdError(int errorCode) {
    if (currentAdSession != null) {
        currentAdSession.failed(
                errorCode,
                "TCL_AD_ERROR_" + errorCode
        );
        currentAdSession = null;
    }

    // 客户原有的广告失败处理继续执行
}
Hq008AdSession 是一次性的。客户只需要在广告成功或失败后调用一次 completed() 或 failed(...)；SDK 内部会自动结束本轮。业务侧如果自己保存了 currentAdSession，建议同步置空，避免重复回调。

6. 完整调用顺序

Application 调用 Hq008FlowSdk.init()
↓
SDK 全局定时 → flow-control → authorize
↓
广告展示组件调用 setAdCallback()
↓
authorized=true 时回调 Hq008AdCallback
↓
客户播放广告并通知 Hq008AdSession
↓
流程 SDK 自动上报并安排下一轮

7. 可选控制

调用用途
Hq008FlowSdk.triggerNow()联调时立即触发一轮；必须已经调用 init()。
Hq008FlowSdk.stop()停止后续定时任务，并结束当前流程会话。

8. 接入检查

  • 已集成并成功初始化 TCL 视频广告 SDK；
  • Application 中已调用 Hq008FlowSdk.init；
  • 能够展示广告的组件已调用 Hq008FlowSdk.setAdCallback；
  • 组件销毁或不再能展示广告时已调用 Hq008FlowSdk.clearAdCallback；
  • 广告加载、开始、完成、失败回调已通知当前 Session；
  • 完成或失败后已将 currentAdSession 置空；
  • 正式环境的 channelId 已确认。
本文只描述流程控制 SDK 的客户调用方式。TCL 广告窗口、容器和播放策略继续由客户现有代码负责。
