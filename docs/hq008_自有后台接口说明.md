# hq008 自有后台接口说明

## 1. 文档目标

本文档用于整理 `hq008` 当前代码里实际调用的我方后台接口，并同步当前最新版 CMP 处理逻辑，方便老板、后台和客户端统一口径。

当前只覆盖这三条明确参与流程的接口：

1. `POST /api/v2/ad/consent-popup`
2. `POST /api/v2/ad/consent-report`
3. `POST /api/v2/ad/sdk/authorize`

---

## 2. 基础说明

- 请求方式：`POST`
- 数据格式：`JSON`
- 当前 `hq008` 这三条接口固定使用的基础域名：
  - `https://api.kytira.cc/`
- 代码中的固定前缀来自：
  - `Hq008ApiConfig.FIXED_BASE_URL`

说明：

- 客户端不会自己决定本次该同意还是拒绝
- 客户端会先读取 CMP SDK 当前状态
- 只有当 SDK 当前这轮仍然需要处理 CMP 时，才会请求 `consent-popup`
- 后台返回结果后，客户端才尝试执行对应 CMP 动作
- CMP 动作真正执行完成后，客户端才会调用 `consent-report`
- CMP 流程结束后，客户端再请求 `sdk/authorize`

---

## 3. 接口一：consent-popup

### 3.1 接口地址

```text
POST /api/v2/ad/consent-popup
```

### 3.2 接口用途

客户端在广告请求前调用这个接口，询问后台：

- 这台设备这一次该不该继续处理 CMP
- 如果要处理，这一轮最终应该走哪一种 CMP 动作

### 3.3 请求参数

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `channel_id` | string | 是 | 当前渠道 ID，客户端取 `BuildConfig.CHANNEL` |
| `mac` | string | 是 | 设备 MAC 地址；如果取不到，客户端当前会传 `00:00:00:00:00:00` |
| `consent_expired` | boolean | 是 | 当前设备本地 consent 是否缺失或已过期 |

### 3.4 consent_expired 的当前口径

这个字段不是“客户端决定要不要同意”，而只是把本地 consent 状态告诉后台。

当前客户端判断规则：

1. 本地没有 consent 文件 -> `true`
2. 本地没有过期时间 -> `true`
3. 当前时间已经超过过期时间 -> `true`
4. 其他情况 -> `false`

典型场景：

- 新安装
- 清除应用数据
- 恢复出厂设置

以上场景下，客户端都会上报：

```json
{
  "consent_expired": true
}
```

### 3.5 请求示例

```json
{
  "channel_id": "TCL_FFA",
  "mac": "00:00:00:00:00:00",
  "consent_expired": true
}
```

### 3.6 响应字段

当前客户端实际消费的核心字段只有：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `consent_action` | string | 后台要求客户端执行的 CMP 动作 |
| `consent_payload` | object | 可选，仅当 `consent_action=SAVE_SETTINGS` 时使用 |

### 3.7 consent_action 当前取值

| 值 | 含义 | 客户端行为 |
| --- | --- | --- |
| `ACCEPT_ALL` | 本次执行同意全部 | 客户端尝试走静默同意 |
| `REJECT` | 本次执行拒绝 | 客户端尝试走静默拒绝 |
| `SAVE_SETTINGS` | 本次执行自定义设置保存 | 客户端按 `consent_payload` 生成自定义静默设置并提交 |
| `MAYBE_LATER` | 本次执行暂不选择 | 客户端按 SDK 的 Exit 语义执行一次“稍后再说” |
| `SKIP_ALREADY_DECIDED` | 本次明确跳过 | 客户端记录本轮跳过，不执行任何 CMP 动作 |

### 3.8 consent_payload 结构

当 `consent_action=SAVE_SETTINGS` 时，后台还需要额外返回：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `purpose_consent_ids` | int[] | 标准 Purpose 明确同意列表 |
| `purpose_li_ids` | int[] | 标准 Purpose 合法利益列表 |
| `custom_purpose_consent_ids` | int[] | 自定义 Purpose 明确同意列表 |
| `custom_purpose_li_ids` | int[] | 自定义 Purpose 合法利益列表 |
| `special_feature_ids` | int[] | Special Feature 允许列表 |
| `vendor_consent_ids` | int[] | Vendor 明确同意列表 |
| `vendor_li_ids` | int[] | Vendor 合法利益列表 |

### 3.9 响应示例

```json
{
  "consent_action": "ACCEPT_ALL"
}
```

或：

```json
{
  "consent_action": "REJECT"
}
```

或：

```json
{
  "consent_action": "SAVE_SETTINGS",
  "consent_payload": {
    "purpose_consent_ids": [1, 3],
    "purpose_li_ids": [2],
    "custom_purpose_consent_ids": [],
    "custom_purpose_li_ids": [],
    "special_feature_ids": [],
    "vendor_consent_ids": [12, 18],
    "vendor_li_ids": [30]
  }
}
```

或：

```json
{
  "consent_action": "MAYBE_LATER"
}
```

或：

```json
{
  "consent_action": "SKIP_ALREADY_DECIDED"
}
```

### 3.10 客户端处理说明

1. 客户端会先看 SDK 当前是否返回 `needShowPop=true`
2. 如果 `needShowPop=false`，客户端直接跳过本轮远端 CMP 决策
3. 如果返回 `ACCEPT_ALL`，客户端尝试走静默同意
4. 如果返回 `REJECT`，客户端尝试走静默拒绝
5. 如果返回 `SAVE_SETTINGS`，客户端按 `consent_payload` 生成自定义静默设置
6. 如果返回 `MAYBE_LATER`，客户端执行一次 SDK Exit 语义，并保留本轮“暂不做最终选择”
7. 如果返回 `SKIP_ALREADY_DECIDED`，客户端记录本轮跳过，不执行任何 CMP 动作
8. 如果返回未知字符串，客户端本轮跳过 CMP 决策
9. 是否真正执行静默动作，还会同时受 `needShowPop`、当前轮次 `cmpCycleKey`、以及这一轮是否已经执行过动作共同控制

## 4. 接口二：consent-report

### 4.1 接口地址

```text
POST /api/v2/ad/consent-report
```

### 4.2 接口用途

客户端在 CMP 动作真正执行完成后，调用这个接口把最终结果上报给我方后台。

注意：

- 不是拿到 `consent-popup` 返回值就立刻上报
- 而是客户端确认本次 CMP 动作已经真正走完后才上报

### 4.3 请求参数

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `channel_id` | string | 是 | 当前渠道 ID |
| `mac` | string | 是 | 设备 MAC 地址；如果取不到，客户端会传 `00:00:00:00:00:00` |
| `android_sdk_version` | int | 是 | 设备 Android API Level，例如 25(7.1) / 26(8.0) |
| `consent_action` | string | 是 | 本次最终执行成功的 CMP 结果 |

### 4.4 consent_action 当前取值

| 值 | 含义 |
| --- | --- |
| `ACCEPT_ALL` | 本次已成功执行同意全部 |
| `REJECT` | 本次已成功执行拒绝 |
| `SAVE_SETTINGS` | 本次已成功执行自定义设置保存 |
| `MAYBE_LATER` | 本次已成功执行暂不选择 |

### 4.5 请求示例

```json
{
  "channel_id": "TCL_FFA",
  "mac": "00:00:00:00:00:00",
  "android_sdk_version": 25,
  "consent_action": "REJECT"
}
```

### 4.6 响应示例

当前客户端只关心接口是否成功，不依赖复杂返回体。

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

### 4.7 客户端处理说明

1. `consent-report` 成功，表示我方后台已收到这次最终 CMP 结果
2. `consent-report` 失败，不影响客户端继续后面的广告授权流程
3. 当前会调用 `consent-report` 的动作是：
   - `ACCEPT_ALL`
   - `REJECT`
   - `SAVE_SETTINGS`
   - `MAYBE_LATER`
4. 当前不会调用 `consent-report` 的动作是：
   - `SKIP_ALREADY_DECIDED`
5. 失败日志会保留，方便排查

## 5. 接口三：sdk/authorize

### 5.1 接口地址

```text
POST /api/v2/ad/sdk/authorize
```

### 5.2 接口用途

CMP 决策流程结束后，客户端调用这个接口，询问后台：

- 当前设备这次是否允许继续广告流程
- 是否开启隐藏模式
- 返回本次请求的授权结果

### 5.3 请求参数

当前客户端实际会上传以下字段：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `request_id` | string | 是 | 客户端本次请求唯一 ID |
| `uuid` | string | 是 | 基于 Android ID 生成的 UUID |
| `channel_id` | string | 是 | 当前渠道 ID |
| `app_id` | string | 是 | 当前应用包名 |
| `app_name` | string | 是 | 当前固定写死为 `hq008` |
| `bundle` | string | 是 | 当前应用包名 |
| `ua` | string | 是 | User-Agent |
| `ifa` | string | 是 | 当前与 `uuid` 一致 |
| `make` | string | 是 | 设备厂商 |
| `model` | string | 是 | 设备型号 |
| `os` | string | 是 | 当前固定为 `Android` |
| `osv` | string | 是 | Android 版本 |
| `language` | string | 是 | 语言，如 `zh-CN` |
| `video_w` | int | 是 | 当前显示宽度 |
| `video_h` | int | 是 | 当前显示高度 |
| `screen_w` | int | 是 | 设备屏幕宽度 |
| `screen_h` | int | 是 | 设备屏幕高度 |
| `local_ip` | string | 否 | 当前设备局域网 IP |
| `mac` | string | 否 | 当前设备 MAC 地址；如果取不到，这里上传空字符串 |

### 5.4 请求示例

```json
{
  "request_id": "client-1778079734780-b5e738ca",
  "uuid": "b2ee7a8f-1e01-4e29-8392-10e1f8a7ee2b",
  "channel_id": "TCL_FFA",
  "app_id": "com.google.android.adffa",
  "app_name": "hq008",
  "bundle": "com.google.android.adffa",
  "ua": "Dalvik/2.1.0 (Linux; U; Android 13; Device Build/XXX)",
  "ifa": "b2ee7a8f-1e01-4e29-8392-10e1f8a7ee2b",
  "make": "google",
  "model": "TCL_FFA",
  "os": "Android",
  "osv": "13",
  "language": "zh-CN",
  "video_w": 1920,
  "video_h": 1080,
  "screen_w": 1920,
  "screen_h": 1080,
  "local_ip": "192.168.1.205",
  "mac": ""
}
```

### 5.5 响应字段

当前客户端实际依赖以下字段：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `request_id` | string | 服务端返回的请求 ID；如果为空，客户端会回填本地生成值 |
| `authorized` | boolean | 本次是否允许继续广告流程 |
| `hidden_mode` | boolean | 是否隐藏模式 |
| `next_request_seconds` | long | 下次请求间隔参考值，当前客户端只记日志，不直接作为本地调度依据 |
| `client_ip` | string | 服务端看到的客户端 IP |

### 5.6 响应示例

```json
{
  "request_id": "client-1778079734780-b5e738ca",
  "authorized": false,
  "hidden_mode": false,
  "next_request_seconds": 4972,
  "client_ip": "82.152.6.133"
}
```

### 5.7 客户端处理说明

1. 如果 `authorized=false`，本轮不展示广告
2. 如果 `authorized=true`，继续后面的广告 SDK 请求
3. `hidden_mode` 直接按服务端返回值使用
4. `next_request_seconds` 当前只做日志输出，不直接接管本地轮询间隔

## 6. 当前三者调用顺序

当前 `hq008` 的核心调用顺序如下：

1. 应用启动时先初始化 CMP，并读取 SDK 当前状态
2. SDK 返回当前这轮是否需要弹窗，即 `needShowPop`
3. 广告轮询触发后，先进入 CMP 前置门禁
4. 如果 `needShowPop=false`，直接跳过本轮远端 CMP 决策
5. 如果 `needShowPop=true`，客户端请求 `consent-popup`
6. 后台返回 `consent_action` 后，客户端再决定执行 `ACCEPT_ALL / REJECT / SAVE_SETTINGS / MAYBE_LATER / SKIP_ALREADY_DECIDED`
7. 如果本轮真正执行了 CMP 动作，并且动作属于需要上报结果的类型，再调用 `consent-report`
8. CMP 决策流程结束后，再请求 `sdk/authorize`
9. `authorized=true` 才继续广告请求

可以直接理解成：

```text
初始化 CMP 状态 -> consent-popup -> 执行 CMP -> consent-report -> sdk/authorize
```

更准确一点是：

```text
应用启动 -> 读取 SDK 当前 CMP 状态 -> 广告触发 -> 需要时请求 consent-popup -> 执行对应 CMP 动作 -> consent-report -> sdk/authorize
```

## 7. 当前注意事项

### 7.1 consent-popup 是决策入口

客户端不会自己决定本次该同意还是拒绝，而是按后台 `consent-popup` 返回值来走。

### 7.2 SDK 当前状态优先于后台动作

即使后台返回了动作，客户端也不会无条件执行。

当前代码会先看 SDK 当前这轮是否还需要弹窗：

- `needShowPop=false`：直接跳过
- `needShowPop=true`：才进入远端动作处理

### 7.3 当前不是“全局只执行一次”，而是“同一轮 CMP 只执行一次”

当前客户端不是单纯看“这台设备以前有没有同意过或拒绝过”，而是按当前 CMP 轮次去重。

当前 CMP 轮次键 `cmpCycleKey` 由这些信息拼出来：

- 当前 `campaignId`
- 当前 consent 过期时间
- 当前是否是新 campaign
- 当前 `needShowPop`
- 当前 `consent_expired`

同一轮里如果已经执行过：

- `ACCEPT_ALL`
- `REJECT`
- `SAVE_SETTINGS`
- `SKIP_ALREADY_DECIDED`

那么本轮后续不会再重复执行其他终态动作。

`MAYBE_LATER` 不属于终态动作，它会单独按上报哈希做一次去重。

### 7.4 consent-report 是结果上报

客户端只有在本次 CMP 动作真正走完后才会上报，不会提前报。

### 7.5 consent_expired 只是状态字段

`consent_expired` 的作用是把“当前本地 consent 是否还有效”告诉后台。

它本身不会直接让客户端自动重新同意或重新拒绝，最终策略仍由后台决定。

典型理解可以简化成：

- 新安装 / 清数据 / 恢复出厂设置后，本地没有 consent，`consent_expired=true`
- 本地 consent 过期了，`consent_expired=true`
- 本地 consent 还有效，`consent_expired=false`

### 7.6 sdk/authorize 在 CMP 之后

当前代码已经明确改成：

- 先完成 CMP 决策
- 再进入广告授权

这样可以避免广告链路先跑，而 CMP 状态还没确定。

### 7.7 hq008 当前接口域名是固定的

虽然 `hq008` flavor 里还有 `BuildConfig.BASE_URL`，但当前这三条链路：

- `consent-popup`
- `consent-report`
- `sdk/authorize`

实际都固定走：

```text
https://api.kytira.cc/
```
